## Proposed flow

1. Warehouse staff enter a supplier receipt once in AdaPOS. Our existing local `adapos-sync` sends its pending/approved rows to the SC backend. After a successful sync, our backend creates/updates the SCPDA inbox item by document number + line sequence + state/content hash. **รออนุมัติ** is visible but blocked from allocation; after a later sync observes CEO approval, update the same row. Include product code, quantity/exact unit, state, original source time and sync time. Replays do not repeat the notification or add another ADA stock movement. Add a receipt-only sync trigger/short schedule on the HQ machine so alerts are timely; don't make the full stock/price sync run more often. This uses the sync we own; only the mobile notice and receipt cadence change are new.
2. HQ opens the matching item, takes/attaches an arrival photo, records actual physical count and can expand optional lot/manufacture/expiry fields. SCPDA stores a verification/allocation record tied to the ADA document; it does not repeat the ADA inventory write.
3. Reconcile document quantity against physical count. On discrepancy, hold allocation and route it to an authorized reconciliation process; don't silently edit official stock. Only reconciled, unreserved quantity can be allocated.
4. For a provisional ADA item such as a placeholder, keep the request/receipt in **รอ CEO ระบุชื่อ/ตรวจรายการซ้ำ** and exclude it from ordinary allocations. Branch's label photo and trade name travel with the product-review request.
5. CEO/product-data authority in the web app or an authorized SCPDA workspace searches the synced product catalog by exact code/barcode/pack details. CEO maps the request to an existing item or confirms a new master-data command. Do not rely on name similarity alone.
6. The current `adapos-sync` is read-only, so apply the CEO-confirmed command through a separate SC-owned local writer on the HQ AdaPOS machine. Give it a narrow credential, duplicate checks, explicit CEO preview/confirmation, idempotency, audit actor and read-back verification. This is an in-house writeback component, not an external vendor API. Bind and publish canonical product code/name/unit only after the local writer reads the saved item back successfully; otherwise keep it **รอยืนยันจากเครื่อง HQ**.
7. For each canonical product and exact unit, query outstanding Preorders and price inquiries the customer accepted. Exclude open price responses, declines, cancellation, fulfilled/previously allocated quantity. Sort oldest request first with stable request/line ID tie-breaker.
8. Preview the plan; allow **เลือกทั้งหมด** when supply covers outstanding demand. For shortage, allocate oldest first, label any partial quantity and leave the remaining quantity queued. Commit atomically on the server after checking active reservations so two HQ users cannot allocate the same stock.
9. After commit, publish branch status **รับเข้า HQ → จัดสรรแล้ว/บางส่วน → รอจัดส่ง**. Only a later dispatch and branch-receipt event can say goods reached the branch. A supplier receipt with many products is queried/allocated per canonical item/unit.

10. Create a separate authenticated **พนักงานรับสินค้า HQ** account and a **CEO** admin account. Grant the CEO all three workspaces (**CEO / คลัง HQ / ผู้จัดการสาขา**) so they can switch freely from an always-visible switcher; branch workspace still asks which branch. Every action remains attributed to the CEO identity. HQ staff and branch managers see only their own workspace. Keep the web's wide review tables/batch queues and the phone's camera/one-item cards, while sharing SC visual tokens, status vocabulary and the same case/item IDs. The selector changes the workspace UI; server capabilities still authorize each action.

The local preview represents the synced receipt, physical count/photo, optional lots, separate CEO review view, role switch and FIFO allocation. Its receipt/product responses and workspace switch are synthetic UI fixtures; it does not create accounts, authorize real roles, write to ADA/SCCRM/SCPDA or upload a photo.
